# CONVENTIONS — Code & Project Conventions

## Language & toolchain

- Swift 5.10+, macOS 13.0 deployment target (Ventura), Xcode 16+.
- UI: **AppKit** (NSWindow/NSView/NSTableView). SwiftUI is allowed ONLY for simple
  auxiliary dialogs (About, small sheets) — never for panels, Lister, or anything
  performance-relevant. See ADR-001.
- Project is generated with **XcodeGen** from `project.yml`. Never edit `.xcodeproj`.
- Dependencies via Swift Package Manager, pinned versions, listed in
  `docs/architecture/tech-stack.md`. New dependency = new ADR.

## Module layout (targets)

```
Sources/
  PCFoundation/    tiny shared utils, logging, config primitives (no AppKit)
  PCVFS/           virtual file system protocol + local FS implementation (no AppKit)
  PCOperations/    file operation engine: copy/move/delete/queue/progress (no AppKit)
  PCArchive/       archive VFS backends (libarchive wrapper, zip writer)
  PCPluginHost/    plugin loading, C-ABI bridging, plugin registry (no AppKit)
  PCNet/           FTP/SFTP backends (built on PCVFS + PCPluginHost API)
  PCCommands/      command registry (cm_*), shortcut mapping, user commands
  PCApp/           the AppKit application: windows, panels, dialogs, Lister UI
Tests/
  <Module>Tests/   one test target per module
  PCPerfTests/     performance benchmarks (see docs/testing/test-strategy.md)
Fixtures/          test fixtures (generated by script, never committed binaries > 100 KB)
Tools/             build/release scripts (dmg, notarize, appcast, fixture generator)
Plugins/           bundled + sample plugins, C headers for the plugin SDK
```

Dependency direction: `PCApp -> everything`, engine modules never import PCApp,
`PCFoundation` imports nothing of ours. AppKit only in PCApp.

## Style

- Follow standard Swift API Design Guidelines; 4-space indent, 120 col soft limit.
- Types prefixed only where ambiguity threatens (modules provide namespacing).
- No force unwraps (`!`) outside tests; no `try!` outside tests and app bootstrap.
- Errors: typed errors per module (`enum PCVFSError: Error`), user-facing mapping
  in PCApp only. Every error path either surfaces to the user or is logged.
- Logging: `os.Logger`, subsystem `com.peachcommander`, category = module name.
  No `print()` in committed code.
- Concurrency: Swift Concurrency (`async/await`, actors). The main thread renders;
  ALL I/O and enumeration off-main. `@MainActor` on UI types only.
- Files < ~400 lines; split by extension/topic when growing beyond.
- Comments: only for invariants, tricky algorithms, and public API docs (`///`).

## UI conventions

- All user-visible strings via `String(localized:)` from day one (localization I19).
- Every command in the UI goes through the command registry (PCCommands) — no
  ad-hoc selectors from menu items to controllers (needed for remapping/buttonbar).
- Look & feel targets `docs/product/ui-reference.md`; theme constants centralized
  in `PCApp/Theme.swift`.

## Testing

- New engine code: unit tests in the same PR/commit. UI: smoke tests per iteration.
- Test fixtures come from `Tools/make-fixtures.sh` (creates temp trees, big files
  sparsely). Tests never touch the user's real home directory outside temp dirs.

## Git

- Commit format: see WORKFLOW.md. Branch `main` only (single-agent workflow);
  if multiple agents work in parallel, one branch per iteration `iter/INN`.
