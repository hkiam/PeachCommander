매크로

매크로는 이름이 붙은 파일 작업의 연속입니다 — 폴더를 만들고, 선택 항목을 그 안으로 옮기고, 남은 것에 태그를 붙이는 식으로 — 한 번의 클릭으로 다시 실행할 수 있습니다. 스크립트 언어가 아닙니다. 조건도 반복도 없으며, 그것은 의도한 것입니다. 매크로는 읽을 수 있는 목록이고, 승인하기 전에 읽을 수 있어야 하는 것이 바로 그것입니다.

매크로가 하는 모든 일은 어시스턴트가 쓰는 것과 같은 장치를 거칩니다. 따라서 매크로는 여러분이 허용하지 않은 일을 할 수 없고, 각 단계는 작업 기록에 남으며, 되돌릴 수 있는 단계는 여전히 되돌릴 수 있습니다.

가장 빠른 길: 방금 한 일에서

매크로를 처음부터 작성할 필요는 없습니다.

  1. 한 번 해 보십시오 — 어시스턴트를 통해서든, 기존 매크로를 실행해서든.
  2. 환경 설정 ▸ 최근 작업으로 매크로 만들기…를 선택합니다.
  3. 매크로가 반복해야 할 단계를 체크하고 이름을 지어 준 다음, 이 매크로용 버튼도 추가를 켠 상태로 둡니다.

매크로 저장을 누르면 버튼이 막대에 생깁니다. 이것이 전부입니다.

기록되지 않는 것. 목록은 어시스턴트나 다른 매크로를 통해 실행된 작업으로 만들어집니다. 패널에서 직접 복사·이동·이름 변경한 것 — F5, F6, F7 — 은 기록되지 않으므로 이 방법으로는 매크로가 되지 않습니다. 그런 경우에는 아래의 편집기를 사용하십시오.

매크로를 직접 편집하기

환경 설정 ▸ 매크로 편집…은 설정 폴더의 macros.json을 열고, 처음에는 주석이 달린 예제를 남겨 둡니다. 매크로는 단계의 목록이고, 각 단계는 도구와 그 인자를 지정합니다:

[
  {
    "id": "stage-by-month",
    "title": "File the selection into a dated folder",
    "icon": "calendar",
    "steps": [
      { "tool": "set_selection", "arguments": { "mask": "*.pdf" } },
      { "tool": "make_directory", "arguments": { "path": "%T/%{date:yyyy-MM}" } },
      { "tool": "move", "arguments": { "sources": "%S", "destination": "%T/%{date:yyyy-MM}" } }
    ]
  }
]

저장하면 매크로가 즉시 다시 읽힙니다. 어떤 도구가 있고 무엇을 받는지는 어시스턴트에게 list_macros로 물어보거나, 파일이 생성될 때 들어간 예제를 읽으면 됩니다.

자리 표시자

낱글자는 버튼 막대와 시작 메뉴가 쓰는 것과 같습니다. 버튼을 만들어 본 적이 있다면 새로 배울 것이 없습니다.

자리 표시자 의미
%P 활성 패널의 폴더
%T 다른 패널의 폴더
%N 커서 아래의 파일
%S 선택된 파일 — 목록이며, copy, move, move_to_trash가 받는 것이 바로 이것입니다
%{date:yyyy-MM} 매크로가 시작된 날짜를 해당 형식으로
%{1} 1단계의 결과 — 그 단계가 경로나 경로 목록을 만들어 낸 경우

중괄호는 추가 항목을 위한 것입니다. 낱글자는 이미 쓰이고 있기 때문입니다. %M은 프로그램의 다른 모든 곳에서 “다른 패널의 커서 아래 이름”을 뜻하므로, 월을 그렇게 쓸 수는 없었습니다.

%S는 매크로가 버튼과 다른 유일한 지점입니다. 버튼에서는 선택 항목이 명령줄용 단어 목록이 되지만, 여기서는 파일 도구가 받는 전체 경로의 목록이 됩니다.

%S나 %{1}이 비어 나오는 단계는 매크로를 멈춥니다 — 아무것도 없이 실행하는 대신에. 파일이 없는 move는 더 작은 move가 아니라 이미 아무 말도 하지 않는 요청이며, 성공했다고 알리는 것은 거짓말이 됩니다.

매크로 실행하기

각 매크로는 mc_<id>라는 이름의 명령이 되므로, 다음 곳에 저절로 나타납니다:

  • 환경 설정 ▸ 명령 브라우저…
  • 환경 설정 ▸ 단축키 편집… — 키에 지정하십시오
  • 버튼 막대 편집기의 명령 선택기
  • 사용하고 있다면 .mnu 메뉴 파일과 usercmd.ini
  • 이름으로 실행할 수 있는 어시스턴트

무언가를 바꾸는 매크로가 실행되기 전에, 매크로는 단계를 목록으로 보여 주고 기다립니다. 원하지 않는 단계는 지울 수 있고, 남은 것이 실행됩니다. 읽기만 하는 매크로는 묻지 않고 실행됩니다.

단계가 실패하면 매크로는 계속 진행하지 않고 그 자리에서 멈춥니다. 두 번째 단계는 보통 첫 번째 단계가 일어났다고 전제하며, 만들어지지 않은 폴더로 파일을 옮기는 것은 부분적인 성공이 아닙니다. 보고서는 단계를 지목하고 무엇이 잘못됐는지 알려 주며, 실행된 단계는 작업 기록에 남습니다.

매크로에 허용되는 것

매크로는 그 안에서 가장 까다로운 것을 기준으로 판단됩니다. 단계가 읽기만 하는 매크로는 읽기로 취급되고, 영구 삭제로 끝나는 매크로는 영구 삭제로 통제됩니다 — 무엇이든 실행되기 전에, 네 단계 뒤가 아니라.

추가로 아무것도 허용하지 않는 것이 기본입니다. 매크로에 여러분의 권한이 허용하지 않는 단계 — 셸 명령, 스크립트 — 가 들어 있으면, 매크로 전체가 이유와 함께 거부되고 아무 일도 일어나지 않습니다.

실행 취소

각 단계가 따로 기록되므로, 매크로 뒤의 실행 취소는 매크로 전체가 아니라 그 마지막 단계를 되돌립니다. 매크로 전체를 되돌리는 기능은 없습니다. 여러 도구에는 역동작이 아예 없고, 그것을 제공하는 버튼은 그런 도구에 대해 거짓을 말하게 되기 때문입니다.

저장 위치

  • 매크로는 설정 폴더의 macros.json에 있습니다 — diff를 볼 수 있고 dotfiles와 함께 보관할 수 있는 평범한 파일입니다.
  • 매크로가 추가한 버튼은 default.bar의 일반적인 버튼 막대 항목이므로, 하나를 없애는 일은 다른 버튼과 다르지 않습니다.
