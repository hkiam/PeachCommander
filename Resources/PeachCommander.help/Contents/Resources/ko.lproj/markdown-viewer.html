뷰어의 Markdown과 HTML

.md 또는 .html 파일에서 F3을 누르면 소스가 아니라 서식이 적용된 모습으로 나타납니다. 제목, 목록, 표, 링크, 작업 목록, 그리고 언어별로 색이 입혀진 코드 블록입니다. ```mermaid 블록으로 작성한 다이어그램은 그려지고, 달러 기호 사이에 쓴 수식은 조판됩니다.

이것은 플러그인입니다. 이 페이지의 모든 내용은 Markdown and HTML에서 오며, 환경 설정 ▸ 플러그인…에서 끌 수 있습니다. 끄면 무엇이 달라지는지는 아래에 있습니다.

서식 보기가 나타나는 곳

  • 뷰어(F3). 서식이 적용된 페이지입니다. 보기 팝업은 여전히 텍스트, 코드, Hex를 제공하므로 소스는 한 번의 클릭 거리이고, 플러그인 이름도 그 목록에 있습니다.
  • Quick View(Ctrl+Q)와 사이드 패널의 정보 페이지는 같은 렌더링을 보여 주므로, 한 파일의 미리 보기와 전체 보기가 서로 어긋나지 않습니다.
  • 갤러리는 일반 문서 아이콘 대신 Markdown 파일 앞부분의 작은 그림을 보여 줍니다.
  • Quick Look(Cmd+Y) 은 macOS 자체의 미리 보기이며 영향을 받지 않습니다. 그 패널은 시스템의 것이고, 어떤 플러그인도 거기에 그릴 수 없습니다.

기호 개요

뷰어에서 기호를 누르면 문서의 제목이 작성된 대로 중첩되어 나타나고, 하나를 클릭하면 페이지의 해당 위치로 이동합니다. 서식 보기와 소스 모두에서 작동하며, 둘은 제목의 위치에 대해 일치합니다.

다이어그램과 수식

언어가 mermaid인 코드 블록은 다이어그램이 되고, $…$와 $$…$$는 조판된 수식이 됩니다. 둘 다 플러그인 안에 포함된 엔진이 여러분의 Mac에서 그립니다. 아무것도 내려받지 않으며, 문서의 어떤 부분도 외부로 전송되지 않습니다. 코드 블록이나 인라인 코드 안의 달러 기호는 달러 기호로 남습니다.

다이어그램도 수식도 없는 문서는 어떤 엔진도 불러오지 않으므로, 평범한 README에는 추가 비용이 없습니다. 읽을 수 없는 다이어그램은 사라지지 않고, 블록이 있던 자리에 오류를 표시하고 그 아래에 블록의 원문을 보여 줍니다.

둘은 환경 설정 ▸ 설정 ▸ Markdown에서 따로 끌 수 있으며, 어떤 버전이 쓰이고 있고 어디서 왔는지도 그곳에서 볼 수 있습니다.

직접 준비한 버전

Mermaid나 KaTeX의 더 새로운 또는 다른 빌드가 필요하면 Engine Folder… 버튼이 여는 폴더에 넣으십시오. 포함된 것 대신 그것이 사용됩니다. 파일 이름은 mermaid.min.js, katex.min.js, katex.min.css, auto-render.min.js입니다. 인터넷에서 무언가를 대신 가져오는 일은 결코 없습니다.

PDF 만들기

커서가 .md 또는 .html 파일 위에 있을 때 명령 ▸ PDF로 내보내기…(패널 컨텍스트 메뉴의 같은 항목도 마찬가지)는 그 문서를 같은 이름의 PDF로 옆에 씁니다. 보통 폴더에서만 제공됩니다 — 압축 파일 안이나 마운트된 드라이브에는 읽을 디스크 상의 파일도, 옆에 쓸 자리도 없습니다. 여러 문서를 표시해 두면 차례로 내보내집니다.

PDF는 F3으로 보는 바로 그 페이지입니다. 같은 스타일시트, 같은 색이 입혀진 코드, 같은 다이어그램과 같은 수식입니다. 기본은 A4로 조판되며(Letter는 설정입니다), 쪽 나눔은 글줄 한가운데가 아니라 문단·목록 항목·표 행 사이에 놓이고, 어느 쪽도 그 절이 시작하는 제목 없이 시작하지 않습니다. 본문 폭보다 넓은 것이 있는 문서 — 열이 많은 표, 끊을 수 없는 긴 줄 — 은 가장자리에서 잘리는 대신 맞도록 축소됩니다. 브라우저의 인쇄가 하는 것과 같습니다.

플러그인 설정 페이지의 PDF 아래:

  • 용지 — A4 또는 US Letter.
  • 같은 이름의 기존 PDF 바꾸기 — 기본은 꺼짐이라, 두 번째 내보내기는 첫 번째를 덮어쓰지 않고 Name 2.pdf로 옆에 기록됩니다.
  • 새 PDF를 패널에 표시 — 방금 기록된 파일로 패널을 옮깁니다. 이 항목을 꺼 두면 대신 짧은 메시지가 나오므로 내보내기가 아무 말 없이 끝나지는 않습니다.

서식 있는 보기에 비해 너무 큰 문서(한계 참조)는 내보낼 수도 없으며, 메시지가 그 파일을 알려 줍니다.

서식 페이지가 하지 않는 일

서식 페이지는 의도적으로 차단되어 있습니다. Markdown 파일은 다른 곳에서 온 내용이기 때문입니다.

  • 네트워크로 아무것도 불러오지 않습니다. 주소가 http로 시작하는 이미지는 의도적으로 비어 있습니다. 가져오면 그 서버에 파일을 언제, 어느 주소에서 열었는지 알려 주게 됩니다. 디스크에서 문서 옆에 있는 이미지는 정상적으로 표시됩니다.
  • 문서 자체의 스크립트와 HTML은 결코 실행되지 않습니다. Markdown 파일 안에 쓴 HTML은 텍스트로 표시되고, .html 파일은 스크립트를 끈 상태로 표시됩니다.

끄기

환경 설정 ▸ 플러그인…에서 플러그인을 끄면 .md와 .html 파일은 텍스트로 열립니다. 개요도 계속 작동하고 구문 색상도 계속 작동하며, 그 밖에 달라지는 것은 없습니다. 서식 보기만 제공되지 않습니다. 플러그인 설정 페이지에서 서식 보기만 끈 경우도 같습니다.

한계

  • 크기 한도(기본 8 MB, 설정 페이지)를 넘는 파일은 대신 텍스트로 열립니다. 아주 큰 생성 문서를 서식 페이지로 바꾸는 일은 느리고, 텍스트 뷰어는 즉시 엽니다.
  • 서식 페이지는 편집할 수 없습니다. 편집에는 F4를 쓰고, 서식, 인코딩, 이동은 텍스트 보기에서 쓰십시오. 이들은 렌더링된 페이지가 아니라 소스에 적용됩니다.
