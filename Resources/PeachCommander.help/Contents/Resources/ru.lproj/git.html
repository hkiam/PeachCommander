Git

Плагин Git показывает состояние репозитория Git прямо в панели файлов — без отдельного приложения и без терминала. Он добавляет две колонки, подменю Git, закреплённую панель для подготовки и фиксации изменений и окна для истории, blame, веток, конфликтов и перебазирования. Он работает через git, уже установленный на вашем Mac. Это плагин, поэтому его можно выключить или удалить в Конфигурация ▸ Плагины….

Что он добавляет

  • Две колонки в списке файлов — Состояние Git и Ветка. У каждого файла показаны значок и короткое слово состояния (Изменён, Добавлен, Удалён, Не отслеживается, Переименован, Скопирован, Конфликт, Игнорируется, Тип изменён), с пометкой (подготовлен), если изменение уже в индексе; колонка Ветка показывает ветку, на которой стоит репозиторий этого файла. Колонки включаются в Конфигурация ▸ Колонки… (см. Режимы просмотра и сортировка).
  • Меню Git — в Команды ▸ Git и в контекстном меню файла.

(Рисунок: «Состояние Git» называет ветку и каждое изменение в рабочем дереве.)

Панель: подготовить, зафиксировать, синхронизировать

Команды ▸ Git ▸ Панель закрепляет вид, который делит рабочее дерево на подготовленное, изменённое и неотслеживаемое. Выберите файлы и используйте Подготовить, Снять подготовку или Отменить…, введите сообщение и нажмите Зафиксировать — с Исправить изменение вкладывается в предыдущую фиксацию. Fetch, Получить и Отправить рядом, там, где фиксация и так происходит; все три показывают ход и их можно прервать.

Фиксируется индекс, а не git commit -a: фиксируется то, что вы подготовили.

История в панели

Под кнопками панель показывает историю всех веток, удалённых веток и тегов в виде нарисованного графа, с рабочей копией в первой строке. Область ниже следует за выделением:

  • Локальные изменения показывает проиндексированные, изменённые и неотслеживаемые файлы и описанное выше поле коммита.
  • Коммит показывает либо Коммит — автора, коммиттера, дату, хеш, родителей, ссылки, подпись и полное сообщение, — либо Изменения.
  • Изменения выводит затронутые файлы деревом и diff выбранного файла с номерами строк; двойной щелчок открывает окно сравнения.
  • Контекстное меню копирует хеш или тему, отменяет, делает cherry-pick, открывает коммит в браузере и ограничивает список пунктом Только текущая ветка.
  • В том же меню на коммит можно переключиться, создать на нём ветку или тег, слить его в текущую ветку, перебазировать или сбросить на него текущую ветку либо начать от него интерактивный rebase.
  • Поле поиска над списком ищет по всей истории — в сообщении, имени и e-mail автора или по хешу и его первым символам — и показывает результаты без графа.

Больше в панели и в меню Git

Рабочая копия, история и меню Команды ▸ Git умеют больше, чем фиксировать:

  • Выбранный проиндексированный или изменённый файл показывает под списком свой diff; выбранные строки или целый фрагмент можно проиндексировать, убрать из индекса или отменить через его контекстное меню.
  • Поле коммита принимает несколько строк — тему, пустую строку, текст, — фиксирует по Cmd+Return и считает символы темы; кнопка меню рядом хранит ваши последние сообщения коммитов.
  • Показать в левой панели и Показать в правой панели переводят файловую панель к файлу из списка или из изменений коммита, а панель Git остаётся как есть; файлы, хранимые Git LFS, отмечены LFS.
  • Stash-и показываются в истории маленькими квадратами над коммитом, на котором созданы, с пунктами Применить stash, Применить и удалить stash и Удалить stash… в контекстном меню.
  • Reflog… перечисляет каждое перемещение HEAD; коммит, потерянный при сбросе или удалении ветки, возвращается через Новая ветка здесь….
  • Настройки репозитория… добавляют, переименовывают, перенаправляют и удаляют удалённые репозитории, добавляют, обновляют и удаляют подмодули, управляют worktree и задают только этому репозиторию имя и e-mail для коммитов.
  • Создать репозиторий здесь… и Клонировать репозиторий… работают в папке активной панели, а часы рядом с заголовком панели возвращают к недавнему репозиторию.

Когда git останавливается, и настройки

  • Push при первой отправке ветки устанавливает upstream. Если в удалённом репозитории есть коммиты, которых нет в этой ветке, он предлагает Получить, затем отправить или Принудительная отправка — всегда с lease, который откажет, если кто-то отправил изменения после вашего последнего fetch; Принудительная отправка (с lease)… есть и в контекстном меню кнопки Push.
  • Если Pull обнаруживает, что ветка и её upstream разошлись, он спрашивает, выполнить слияние или rebase, вместо того чтобы остановиться на сообщении git.
  • Слияние, cherry-pick, revert, rebase или серия патчей, остановившиеся на конфликте, показывают над историей баннер с кнопками Продолжить и Прервать…; коммит слияния отменяется или переносится относительно первого родителя.
  • Выберите два коммита, чтобы сравнить их, или несколько, чтобы перенести их за раз через cherry-pick. Сравнить с рабочей копией и Сохранить как патч… находятся в меню истории, Применить патчи… — в меню Git.
  • Поле поиска принимает и фильтры — author:name, path:folder/, since:"2 weeks ago", until:2026-10-01 — по отдельности или вместе со словами.
  • Bisect: отметить как плохой и Bisect: отметить как хороший в меню истории запускают bisect; затем баннер предлагает Хороший, Плохой, Пропустить и Завершить bisect, пока git не назовёт первый плохой коммит.
  • Отложить в stash выбранные файлы или все изменения: появится запрос сообщения и вопрос, включать ли неотслеживаемые файлы и сохранять ли индекс. Файлы в Git LFS можно заблокировать и разблокировать, а их тип файла — отслеживать.
  • В списке веток ветку можно переименовать (Переименовать…), задать ей upstream (Установить upstream…) или удалить на её сервере (Удалить на удалённом репозитории…).
  • Настройки ▸ Git задают программу git, ваше глобальное имя и e-mail, работу Pull, получение в фоне, что показывает история и как выглядят её даты, подпись, sign-off и хуки коммитов, а также пробелы и строки контекста в диффах. Авторы в истории отмечены цветными инициалами.

Файлы, слияние, Git flow и pull request

  • Файлы рядом с «Коммит» и «Изменения» показывают всё дерево в выбранном коммите; файл открывается с номерами строк, а его меню сравнивает его с рабочей копией, сохраняет в другое место или возвращает в рабочую копию (Восстановить эту версию…).
  • Редактор слияния… — на файле с конфликтом в панели, в баннере, в Разрешить конфликт… и в меню Git — показывает текущий конфликт как нашу версию, базу и их версию рядом, а под ними весь файл для редактирования. Взять наши, Взять их, обе в любом порядке или Взять базу решают конфликт, а Сохранить и индексировать отмечает файл как разрешённый, когда маркеров не осталось.
  • Символ ветки в заголовке панели — это меню Git flow: Начать функцию…, Начать релиз… и Начать исправление… создают ветку от develop или main, а Завершить … сливает её обратно — релиз или исправление в main с тегом, затем в develop. Повторное завершение после конфликта продолжает с того места, где оно остановилось.
  • Pull request… в меню Git показывает открытые pull request (merge request в GitLab) и задачи проекта, на который указывают удалённые репозитории, с проверками каждого; извлекает pull request в собственную ветку и открывает новый для текущей ветки.
  • Для этого нужен персональный токен доступа, который вводится в этом окне и хранится в связке ключей; токен отправляется только в API сервиса. С токеном символ рядом с веткой в заголовке панели показывает, прошёл ли CI для текущего коммита.
  • Настройки ▸ Git задают имена веток и префиксы Git flow, а в разделе Хостинг — собственные серверы GitLab или GitHub Enterprise.

История, blame и веб

  • История… перечисляет фиксации с графом дорожек, ссылки, указывающие на каждую (● main, ↗ origin/main, ⚑ v1.0), и файлы, которых коснулась каждая фиксация. Return или двойной щелчок открывает версию этого файла против её предшественницы в окне сравнения. Откатить фиксацию и Cherry-pick тоже там, и оба отказываются заранее, если рабочее дерево не чисто.
  • История файла… — то же окно для одного файла.
  • Blame (список)… показывает каждую строку с её фиксацией, автором и датой. Blame в редакторе помещает те же сведения на поле редактора, рядом с номерами строк: наведение на строку показывает сообщение фиксации, щелчок открывает её против предшественницы.
  • Открыть в вебе открывает файл, фиксацию или ветку на GitHub, GitLab, Bitbucket или Azure DevOps, собрав адрес из URL удалённого репозитория — без учётной записи и без токена. Для узла, устройство ссылок которого ему неизвестно, он предлагает страницу репозитория, а не гадает.

Ветки, отложенные изменения и метки

Ветки, отложенные изменения и метки… перечисляет всё трое. Переключить, создать, слить или удалить ветку; отправить, извлечь или отбросить отложенное; создать, удалить или отправить метку либо переключиться на неё — метка не ветка, поэтому заранее сказано, что HEAD останется отсоединённым. Выборка, Получить и Отправить — в том же окне, и их можно прервать на ходу.

Отправка метки намеренно сделана отдельным действием: git push метки с собой не берёт.

Конфликты

Разрешить конфликт… перечисляет конфликтные области файла под курсором и принимает решение по каждой: наше, их, оба — или оставить открытой. Затем Записать файл или Записать и подготовить. Плагин отказывается подготавливать, пока хоть одна область открыта — Git с готовностью зафиксирует метки <<<<<<< — и скорее не тронет файл, чьи метки он не может прочесть, чем станет их угадывать. Для области, где обе стороны нужно переплести вручную, Открыть в редакторе — одна кнопка.

Перебазирование

Перебазировать… перечисляет фиксации впереди вышестоящей ветки — те, которых больше ни у кого пока нет — и позволяет их сжать, присоединить как правку, отбросить, переставить или переписать сообщение, прежде чем ветка будет переписана. Если перебазирование остановится на конфликте, то же окно становится Продолжить / Пропустить фиксацию / Прервать, чтобы недоделанное перебазирование не пришлось завершать в терминале.

Игнорирование файлов и учётные данные

  • Игнорировать этот файл…, Игнорировать этот тип файлов… и Игнорировать эту папку… вписывают нужный шаблон в .gitignore — привязанный там, где положено, чтобы игнорирование этой папки build не игнорировало каждую папку с именем build.
  • Учётные данные… сообщают, как этот репозиторий проходит проверку подлинности: SSH или HTTPS, настроен ли помощник учётных данных, запущен ли агент SSH и держит ли он ключ. Где это помогает, предлагается ровно одно действие — позволить Git хранить учётные данные в связке ключей macOS. Плагин никогда не спрашивает парольную фразу, не показывает и не сохраняет её.

Примечания

  • Плагин использует системный Git по пути /usr/bin/git или программу, выбранную в Настройки ▸ Git. Если Git не установлен, команды сообщают, что Git недоступен. (Его содержат Xcode Command Line Tools.)
  • Состояние репозитория читается один раз на папку и кэшируется, чтобы прокрутка большого репозитория оставалась быстрой; кэш обновляется после любой команды, меняющей дерево, и следует за фиксацией, сделанной вне приложения.
  • Связанные рабочие деревья и подмодули поддерживаются: файл внутри подмодуля показывает состояние и ветку подмодуля, а не родительского репозитория.
  • У каждого списка есть контекстное меню, Return выполняет основное действие, а Cmd+R обновляет окно.
  • Git LFS, gpg для подписанных коммитов и помощники учётных данных находятся в папках Homebrew и MacPorts, даже если приложение открыто из Finder.
