宏

宏是一串带名字的文件操作——新建文件夹、把选中项移进去、给剩下的加标记——你可以一键再跑一次。它不是脚本语言：没有条件，也没有循环，这是有意为之。宏是一份你能读懂的清单，而在你同意之前，能读懂正是必须做到的事。

宏所做的一切都走助手所用的同一套机制，所以宏做不了任何你没有许可的事，它的每一步都会进入操作记录，能撤销的一步依然能撤销。

最快的路：从你刚做过的事开始

你不必从零写一个宏。

  1. 先做一次——通过助手，或者运行一个已有的宏。
  2. 选择 配置 ▸ 从最近的操作创建宏…。
  3. 勾选宏应当重复的步骤，给它取个名字，并保持 同时为它添加一个按钮 处于开启状态。

保存宏，按钮就在工具条上了。这就是全部流程。

哪些不会被记录。 清单由经过助手或其他宏执行的操作构成。在面板中手动复制、移动或重命名——F5、F6、F7——不会被记录，因此无法用这种方式变成宏。那些请用下面的编辑器。

手动编辑宏

配置 ▸ 编辑宏… 会打开配置文件夹中的 macros.json，第一次还会在其中留下一个带注释的示例。宏是一串步骤，每一步指明一个工具及其参数：

[
  {
    "id": "stage-by-month",
    "title": "File the selection into a dated folder",
    "icon": "calendar",
    "steps": [
      { "tool": "set_selection", "arguments": { "mask": "*.pdf" } },
      { "tool": "make_directory", "arguments": { "path": "%T/%{date:yyyy-MM}" } },
      { "tool": "move", "arguments": { "sources": "%S", "destination": "%T/%{date:yyyy-MM}" } }
    ]
  }
]

保存后宏会立即重新载入。有哪些工具、它们接受什么，可以让助手用 list_macros 告诉你——或者读一读文件创建时附带的示例。

占位符

单个字母与按钮条和“开始”菜单使用的完全一致：做过按钮的人在这里没有新东西要学。

占位符 含义
%P 活动面板的文件夹
%T 另一个面板的文件夹
%N 光标下的文件
%S 选中的文件——一个列表，而 copy、move 和 move_to_trash 接受的正是列表
%{date:yyyy-MM} 宏启动的日期，按该格式
%{1} 第 1 步的结果，前提是那一步产生了一个路径或一组路径

花括号留给这些扩展，因为字母已经被占用了：%M 在程序其余各处都表示“另一个面板中光标下的名称”，所以月份不能那样写。

%S 是宏与按钮唯一不同的地方：在按钮上，选中项会变成命令行用的一串词；在这里，它变成文件工具所接受的完整路径列表。

某一步的 %S 或 %{1} 为空时会让宏停下，而不是对着空无一物运行。没有文件的 move 不是更小的 move，而是一条不再表达任何意思的请求，为它报告成功就是撒谎。

运行一个宏

每个宏都会成为名为 mc_<id> 的命令，因此会自动出现在：

  • 配置 ▸ 命令浏览器…
  • 配置 ▸ 编辑快捷键…——把它放到某个按键上
  • 按钮条编辑器的命令选择器
  • 你的 .mnu 菜单文件和 usercmd.ini（如果你在用）
  • 助手，它可以按名字运行这个宏

在一个会作出改动的宏运行之前，它会把自己的步骤列成清单并等待。你可以划掉不想要的步骤；剩下的就是会执行的。只读取的宏不询问就直接运行。

如果某一步失败，宏会停在那里而不是继续——第二步通常假定第一步已经发生，把文件移进一个没有建好的文件夹并不是部分成功。报告会指出是哪一步、出了什么问题，已经跑过的步骤都在操作记录里。

宏被允许做什么

宏按其中最苛刻的那件事来衡量。步骤只做读取的宏视为读取；以永久删除结尾的宏按永久删除来把关——在其中任何一步运行之前，而不是走到第四步才发现。

默认不额外授予任何权限。如果宏中含有你的权限不允许的步骤——一条 shell 命令、一个脚本——整个宏会连同原因一并被拒绝，什么都不会发生。

撤销

每一步都单独记录，所以宏之后的撤销收回的是它的最后一步，而不是整个宏。没有整宏撤销，因为有几个工具根本没有逆操作，提供这样一个按钮就是在这些工具上撒谎。

保存在哪里

  • 你的宏在配置文件夹的 macros.json 里——一个普通文件，可以 diff，也可以和你的 dotfiles 放在一起。
  • 宏添加的按钮就是 default.bar 中普通的按钮条条目，所以删掉一个和删掉任何别的按钮一样。
