# Distribution — Signing, Notarization, DMG, Sparkle Updates

Covers: F-310..F-316. Executed in I20 (scripts may be drafted earlier).
Referenced from feature inventory as DIST.

## 1. Identity & signing (F-310)

- Distribution outside Mac App Store: **Developer ID Application** certificate
  (user must provide Apple Developer account — flagged in STATE.md open
  decisions). Team ID goes into `project.yml` settings + `Tools/release.env`.
- Hardened runtime ON. Entitlements: `com.apple.security.cs.disable-library-validation`
  = **true** (required to load third-party plugin dylibs! document the security
  tradeoff in help), no sandbox (ADR-006). Sparkle XPCs signed as shipped.
- Every dylib/framework/plugin in the bundle signed inside-out
  (`codesign --deep` avoided; explicit inside-out order in script).

## 2. Notarization

`Tools/release.sh` pipeline:
```
xcodegen && xcodebuild -configuration Release archive
codesign (inside-out, timestamp, options runtime)
ditto -> PeachCommander.zip
xcrun notarytool submit --keychain-profile PC_NOTARY --wait
xcrun stapler staple PeachCommander.app
Tools/make-dmg.sh -> PeachCommander-<version>.dmg
xcrun notarytool submit dmg --wait && stapler staple dmg
spctl -a -vv + stapler validate  (gate)
```
`notarytool store-credentials` documented in the script header (app-specific
password or App Store Connect API key).

## 3. DMG (F-311)

`create-dmg`-style script (own, no dep): volume icon, background png
(`Resources/dmg-background.png`), app at left, `/Applications` symlink right,
window size/pos set via AppleScript/dsstore template. DMG format ULMO
(lzma) for size. Name: `PeachCommander-1.0.0.dmg`.

## 4. Sparkle 2 (F-312)

- SPM dependency added in I20; `SUUpdater` → `SPUStandardUpdaterController`.
- Info.plist: `SUFeedURL` (channel-dependent), `SUPublicEDKey` (EdDSA public
  key; private key generated by `generate_keys`, stored ONLY in user's
  Keychain/CI secret — never in repo), `SUEnableInstallerLauncherService`.
- Appcast: `Tools/make-appcast.sh` wraps Sparkle's `generate_appcast` over a
  `releases/` folder → `appcast.xml` (+ `appcast-beta.xml` channel via
  `sparkle:channel`). Hosting: GitHub Releases for DMGs + GitHub Pages for
  appcast (URLs configured in release.env). Delta updates: generate_appcast
  produces them automatically when previous versions present.
- UI: "Check for Updates…" in app menu; Settings>Misc: auto-check cadence,
  channel picker (stable/beta), "Automatically download" toggle.
- Rollback story: keep last 3 releases in feed; document manual re-download.

## 5. Versioning & changelog (F-314)

- Semver `MARKETING_VERSION`; `CURRENT_PROJECT_VERSION` = monotonically
  increasing integer (CI sets from commit count or manual bump).
- `CHANGELOG.md` (keep-a-changelog format); release notes HTML for Sparkle
  generated from it (`Tools/changelog-to-notes.sh`), embedded per appcast item.

## 6. Crash reporting (F-313)

v1: on launch, scan `~/Library/Logs/DiagnosticReports` for our .ips since last
run; dialog offers to reveal/copy for a GitHub issue (consent-first, no SaaS).
Breadcrumb log (recent commands, plugin loads) attached from our file log.
Post-1.0 ADR may add a proper reporter.

## 7. CI release pipeline (F-315)

`release.yml` (tag-triggered `v*`): macos runner, secrets: DEVID cert (p12),
notary API key, Sparkle private key. Steps: test → release.sh → upload DMG to
GitHub Release → regenerate appcast → deploy Pages. Manual fallback: run
`Tools/release.sh` locally with `release.env`.

## 8. First-run experience (ties to F-299)

Gatekeeper-friendly: stapled app opens without warning. First run: onboarding
sheet (keyboard scheme choice TC-classic/macOS-native, Full Disk Access
explainer, update-check consent — Sparkle requires explicit consent flow).
