파일을 단순히 보는 것이 아니라 변경해야 할 때, Peach Commander는 기본 제공 편집기에서 파일을 엽니다. 텍스트 및 코드 파일은 구문 강조, 찾기 및 바꾸기, 코드 내 심볼 개요, 빠른 탐색을 위한 미니맵을 갖춘 완전한 편집기에서 열립니다. 이진 파일은 개별 바이트를 검사하고 변경할 수 있는 별도의 16진수 편집기에서 열 수 있습니다. 빠른 편집을 위해 앱을 떠날 필요가 전혀 없습니다.

## 텍스트 또는 코드 파일 편집

1. 어느 패널에서든 변경할 파일로 커서를 이동합니다.
2. F4를 누르거나 파일 ▸ Edit를 선택합니다. 파일이 편집기 창에서 열립니다.
3. 변경합니다. 파일이 인식된 프로그래밍 또는 데이터 형식이면 키워드, 문자열, 주석이 자동으로 색이 지정됩니다.
4. Cmd+S를 누르거나(또는 저장을 클릭하여) 변경 내용을 기록합니다. 첫 저장 시 원본의 백업을 파일 옆에 보관하므로, 언제든 되돌아갈 수 있습니다.

현재 위치에 완전히 새로운 텍스트 파일을 시작하려면 Shift+F4를 누르십시오.

## 찾기, 바꾸기, 탐색

- Cmd+F를 눌러 찾기 막대를 엽니다. 텍스트를 바꾸려면 찾기 막대를 열고 바꾸기 보기로 전환하거나, 도구 모음에서 찾기/바꾸기를 클릭합니다.
- JSON/XML 서식을 클릭하면 JSON 또는 XML 문서를 깔끔하고 읽기 쉬운 레이아웃으로 다시 들여씁니다.
- 심볼(또는 Cmd+Shift+O)을 클릭하면 코드 내 클래스, 함수, 메서드를 나열하는 사이드바가 표시됩니다. 항목을 클릭하면 바로 이동합니다.
- Cmd+L을 눌러 특정 줄로 이동합니다.
- Cmd+\를 눌러 괄호와 그 짝 사이를 이동합니다.
- 지도 버튼을 클릭하면 미니맵을 표시하거나 숨깁니다. 미니맵은 파일 전체의 축소된 개요로, 클릭하여 스크롤할 수 있습니다.
- 파일이 기본 텍스트 인코딩이 아닌 다른 것으로 저장된 경우 도구 모음의 인코딩 메뉴를 사용하십시오.

## 파일 서식 정리

편집기에서 **서식**을 누르면(뷰어에도 같은 명령이 있습니다) 파일을 다시 들여씁니다. Peach Commander는 확장자로 서식 도구를 고르고, 어느 것을 썼는지 상태줄에 보여 줍니다 — 예를 들어 *formatted (jq)* — 그래서 결과를 무엇이 다듬었는지 늘 알 수 있습니다.

**아무것도 설치하지 않아도** JSON, XML, SVG, plist, HTML, INI 형태의 설정, YAML이 됩니다. YAML은 예외입니다. 다시 들여쓰는 대신 정리만 합니다. YAML에서는 들여쓰기가 *곧* 구조이고, 진짜 YAML 파서 없이 다시 쓰면 파일의 뜻이 바뀔 수 있기 때문입니다. 줄 끝 공백은 사라지고, 들여쓰기에 섞인 탭은 공백이 되고, 빈 줄이 여러 개면 줄어듭니다. 블록 스칼라(`|` 또는 `>`) 안은 그대로 둡니다. 거기서는 공백이 내용이니까요.

**더 나은 도구가 있으면 자동으로 넘어갑니다.** 아래 중 하나가 설치되어 있으면 Peach Commander가 그것을 씁니다. 전용 도구가 보통 생태계의 기대에 맞고, 설정 형식에서는 주석을 지켜 주기 때문입니다:

| 설치하면 | 이렇게 됩니다 |
| --- | --- |
| `yq` 또는 `prettier` | 완전한 YAML 서식, 주석 유지 |
| `taplo` | TOML |
| `sqlformat` 또는 `sql-formatter` | SQL |
| `prettier` | Markdown |
| `jq` | 관례적인 스타일의 JSON |
| `xmllint` | XML과 SVG |

서식 도구가 없는 형식이면 버튼이 흐려지고 메뉴 항목도 꺼집니다. 그래도 시도하면 이유를 알려 줍니다 — *“taplo가 설치되어 있지 않습니다”*는 *“올바른 JSON이 아닙니다”*와 다른 이야기입니다.

### 직접 만든 서식 도구 쓰기

Peach Commander가 모르는 형식을 다루거나 다른 도구를 쓰려면 설정 폴더에 `formatters.ini`를 만드십시오. 확장자마다 한 구역씩입니다:

```ini
[swift]
tool = swiftformat
args = --quiet stdin

[sql]
tool = /opt/homebrew/bin/sqlfluff
args = format -
```

`tool`은 실행 파일 이름(셸이 찾는 방식으로 찾습니다)이거나 절대 경로이고, `args`는 그대로 전달됩니다. 파일의 텍스트는 표준 입력으로 들어가고 정리된 텍스트는 표준 출력에서 읽으므로, 예의를 지키는 명령줄 서식 도구라면 무엇이든 됩니다. 여기 적은 항목이 다른 모든 것을 이깁니다. 처음 실행할 때 주석이 달린 서식 파일이 만들어지니, 열어서 채우면 됩니다.

플러그인도 서식 도구를 제공할 수 있습니다 — [Plugins](plugins.md) 참조.

## 파일을 바이트 단위로 편집

1. 패널에서 파일을 선택합니다.
2. 파일 ▸ Edit as Hex를 선택합니다(또는 파일을 마우스 오른쪽 버튼으로 클릭하고 Edit as Hex를 선택합니다).
3. 16진수 자릿수를 입력하여 바이트를 덮어쓰거나, 화살표 키로 파일을 이동합니다. Backspace와 Delete는 바이트를 제거합니다.
4. Cmd+S를 눌러 저장합니다. 텍스트 편집기와 마찬가지로 원본의 일회성 백업이 보관됩니다.

## 단축키

| 작업 | 키 |
|---|---|
| 파일 편집 | F4 |
| 새 텍스트 파일 만들고 편집 | Shift+F4 |
| 저장 | Cmd+S |
| 찾기 | Cmd+F |
| 심볼 개요 표시/숨기기 | Cmd+Shift+O |
| 줄로 이동 | Cmd+L |
| 짝 괄호로 이동 | Cmd+\ |
| 실행 취소 / 다시 실행(16진수 편집기) | Cmd+Z / Cmd+Shift+Z |

## 참고

- 구문 강조는 JSON, C, C#, Java, JavaScript, TypeScript, Python, Rust를 지원합니다. 다른 파일 유형도 기본 색상으로 정상적으로 열리고 편집되지만, 상세한 강조와 심볼 개요는 지원되는 언어에서만 사용할 수 있습니다.
- 심볼 개요와 줄로 이동 기능은 텍스트 편집기에 적용됩니다. 16진수 편집기는 텍스트가 아니라 이진 검사와 바이트 수준 편집을 위한 것입니다.
- 두 편집기 모두 처음 저장할 때 원본 파일의 백업을 보관하므로, 실수로 변경한 것은 해당 백업을 복원하여 쉽게 되돌릴 수 있습니다.
