Git 플러그인은 Git 저장소의 상태를 파일 패널 안에 그대로 보여 줍니다. 별도의 앱도, 터미널도 필요 없습니다. 열
두 개와 **Git** 하위 메뉴, 스테이징과 커밋을 위한 고정 패널, 그리고 히스토리·블레임·브랜치·충돌·리베이스 창을
더합니다. Mac에 이미 설치된 `git`을 사용합니다. 플러그인이므로 **환경설정 ▸ 플러그인…**에서 끄거나 제거할 수
있습니다.

## 무엇이 추가되는가

- **파일 목록의 두 열** — *Git 상태*와 *브랜치*. 각 파일에는 아이콘과 짧은 상태 낱말(수정됨, 추가됨, 삭제됨,
  추적 안 함, 이름 바뀜, 복사됨, 충돌, 무시됨, 유형 바뀜)이 표시되며, 변경이 이미 인덱스에 있으면
  *(스테이징됨)*이 붙습니다. *브랜치* 열은 그 파일의 저장소가 올라가 있는 브랜치를 보여 줍니다. 열은
  **환경설정 ▸ 열…**에서 켭니다(
  [보기 모드와 정렬](view-modes-and-sorting.md) 참고).
- **Git 메뉴** — **명령 ▸ Git** 아래, 그리고 파일의 오른쪽 클릭 메뉴에 있습니다.

![현재 브랜치와 저장소의 변경된 파일을 보여 주는 Git 상태 창](screenshots/git-status.png)
*(그림: Git 상태는 브랜치와 작업 트리의 모든 변경을 알려 줍니다.)*

## 패널: 스테이징, 커밋, 동기화

**명령 ▸ Git ▸ 패널**은 작업 트리를 *스테이징됨*, *변경됨*, *추적 안 함*으로 묶어 보여 주는 뷰를 고정합니다.
파일을 고르고 **스테이징**, **스테이징 해제**, **버리기…**를 쓰고, 메시지를 입력한 뒤 **커밋**을 누르십시오.
**수정 커밋**을 쓰면 변경이 이전 커밋에 접혀 들어갑니다. **Fetch**, **풀**, **푸시**도 커밋이 어차피 일어나는 그 자리에
나란히 있으며, 셋 모두 진행 상황을 보여 주고 취소할 수 있습니다.

커밋되는 것은 *인덱스*이지 `git commit -a`가 아닙니다. 스테이징한 것이 커밋됩니다.

## 패널의 기록

버튼 아래에 패널은 모든 브랜치, 원격 브랜치, 태그의 기록을 그려진 그래프로 보여 주며, 첫 행은 작업 사본입니다. 그 아래 영역은 선택을 따라갑니다:

![브랜치 그래프, 선택한 병합 커밋, 인라인 diff가 있는 변경된 파일을 보여 주는 Git 패널](screenshots/git-panel.png)

- **로컬 변경 사항**은 스테이징된 파일, 변경된 파일, 추적되지 않는 파일과 위에서 설명한 커밋 입력란을 보여 줍니다.
- 커밋은 **커밋**(작성자, 커미터, 날짜, 해시, 부모, 참조, 서명, 전체 메시지) 또는 **변경 사항**을 보여 줍니다.
- **변경 사항**은 변경된 파일을 트리로, 선택한 파일의 diff를 줄 번호와 함께 보여 주며, 이중 클릭하면 비교 창이 열립니다.
- 컨텍스트 메뉴는 해시나 제목을 복사하고, 되돌리고, 체리픽하고, 웹에서 커밋을 열고, 목록을 **현재 브랜치만**으로 제한합니다.
- 같은 메뉴에서 커밋을 체크아웃하거나, 새 브랜치나 태그를 만들거나, 현재 브랜치로 병합하거나, 현재 브랜치를 그 위로 리베이스하거나 재설정하거나, 대화형 리베이스를 시작할 수 있습니다.
- 목록 위의 검색 필드는 전체 기록에서 메시지, 작성자 이름과 이메일, 또는 해시와 그 앞부분을 검색하고 결과를 그래프 없이 나열합니다.

## 패널과 Git 메뉴의 추가 기능

작업 사본, 기록, **명령 ▸ Git** 메뉴는 커밋 외에도 더 많은 기능을 제공합니다:

- 스테이징되었거나 변경된 파일을 선택하면 목록 아래에 diff가 표시되며, 선택한 줄이나 헝크 전체를 컨텍스트 메뉴에서 스테이징, 스테이징 취소 또는 버릴 수 있습니다.
- 커밋 상자는 여러 줄 — 제목, 빈 줄, 본문 — 을 받으며 **Cmd+Return**으로 커밋하고 제목의 글자 수를 셉니다. 옆의 메뉴 버튼에 최근 커밋 메시지가 있습니다.
- **왼쪽 패널에 표시**와 **오른쪽 패널에 표시**는 Git 패널을 그대로 둔 채 파일 패널을 목록이나 커밋 변경 사항의 파일로 이동하며, Git LFS가 저장하는 파일에는 **LFS** 표시가 붙습니다.
- 스태시는 기록에서 만들어진 커밋 위에 작은 사각형으로 나타나며, 컨텍스트 메뉴에 **스태시 적용**, **스태시 적용 후 제거**, **스태시 삭제…**가 있습니다.
- **Reflog…**는 HEAD의 모든 이동을 나열하며, 재설정이나 삭제된 브랜치로 잃은 커밋은 **여기에 새 브랜치…**로 되살릴 수 있습니다.
- **저장소 설정…**은 원격을 추가, 이름 변경, URL 변경, 제거하고, 하위 모듈을 추가, 업데이트, 제거하며, 워크트리를 관리하고, 이 저장소에만 커밋용 이름과 이메일을 지정합니다.
- **여기에 저장소 만들기…**와 **저장소 복제…**는 활성 패널의 폴더에서 작동하며, 패널 제목 옆의 시계는 최근 저장소로 돌아갑니다.

## git이 멈출 때, 그리고 설정

- **Push**는 브랜치를 처음 푸시할 때 업스트림을 설정합니다. 원격에 이 브랜치에 없는 커밋이 있으면 **풀한 다음 푸시** 또는 **강제 푸시**를 제안하며, 항상 lease를 사용하므로 마지막 페치 이후 누군가 푸시했다면 거부합니다. **강제 푸시(lease 사용)…**는 **Push**의 컨텍스트 메뉴에도 있습니다.
- **Pull**이 브랜치와 업스트림이 갈라졌음을 발견하면 git의 메시지에서 멈추지 않고 병합할지 리베이스할지 묻습니다.
- 충돌로 멈춘 병합, 체리픽, 되돌리기, 리베이스 또는 패치 시리즈는 기록 위에 **계속**과 **중단…** 버튼이 있는 배너를 표시합니다. 병합 커밋은 첫 번째 부모를 기준으로 되돌리거나 체리픽합니다.
- 커밋 두 개를 선택하면 비교하고, 여러 개를 선택하면 한 번에 체리픽합니다. **작업 사본과 비교**와 **패치로 저장…**은 기록 메뉴에, **패치 적용…**은 Git 메뉴에 있습니다.
- 검색 필드는 필터도 받습니다 — `author:name`, `path:folder/`, `since:"2 weeks ago"`, `until:2026-10-01` — 단독으로 또는 단어와 함께 쓸 수 있습니다.
- 기록 메뉴의 **Bisect: 나쁨으로 표시**와 **Bisect: 좋음으로 표시**로 bisect를 시작합니다. 그러면 배너가 git이 첫 번째 나쁜 커밋을 찾을 때까지 **좋음**, **나쁨**, **건너뛰기**, **Bisect 끝내기**를 제공합니다.
- 선택한 파일이나 모든 변경 사항을 스태시하면 메시지를 묻고, 추적되지 않는 파일을 포함할지 또는 인덱스를 유지할지 묻습니다. Git LFS의 파일은 잠그고 잠금 해제할 수 있으며 파일 형식을 추적할 수 있습니다.
- 브랜치 목록에서 브랜치의 이름을 바꾸거나(**이름 변경…**), 업스트림을 지정하거나(**업스트림 설정…**), 서버에서 삭제할 수 있습니다(**원격에서 삭제…**).
- **설정 ▸ Git**에서는 git 프로그램, 전역 이름과 이메일, **Pull** 방식, 백그라운드 페치, 기록에 표시할 내용과 날짜 모양, 커밋 서명, sign-off, 훅, 그리고 diff의 공백과 컨텍스트 줄 수를 정합니다. 기록의 작성자에는 색깔 있는 이니셜이 붙습니다.

## 히스토리, 블레임, 그리고 웹

- **히스토리…**는 커밋을 레인 그래프와 함께, 각 커밋을 가리키는 레퍼런스(`● main`, `↗ origin/main`,
  `⚑ v1.0`), 그리고 각 커밋이 건드린 파일과 함께 나열합니다. Return이나 두 번 클릭하면 그 파일의 판본이 비교
  창에서 부모와 마주 놓입니다. **커밋 되돌리기**와 **체리픽**도 거기 있으며, 작업 트리가 깨끗하지 않으면 둘 다
  미리 거절합니다.
- **파일 히스토리…**는 파일 하나를 위한 같은 창입니다.
- **블레임(목록)…**은 모든 줄을 그 커밋, 작성자, 날짜와 함께 보여 줍니다. **편집기에서 블레임**은 같은 정보를
  줄 번호 옆, 편집기의 여백에 넣습니다. 줄 위에 포인터를 두면 커밋 메시지가 나오고, 클릭하면 그 커밋이 부모와
  마주 놓입니다.
- **웹에서 열기**는 파일, 커밋, 브랜치를 GitHub, GitLab, Bitbucket, Azure DevOps에서 엽니다. 주소는 리모트의
  URL에서 만들며 계정도 토큰도 필요 없습니다. 링크 구성을 모르는 호스트라면 짐작하는 대신 저장소 페이지를
  제안합니다.

## 브랜치, 스태시, 태그

**브랜치, 스태시 및 태그…**는 셋을 모두 나열합니다. 브랜치를 전환·생성·병합·삭제하고, 스태시를 푸시·팝·폐기하며,
태그를 만들고 지우고 푸시하거나 그리로 전환할 수 있습니다. 태그는 브랜치가 아니므로 HEAD가 분리된다고 미리
알립니다. 페치, 풀, 푸시가 같은 창에 있으며 실행 중에 취소할 수 있습니다.

태그 푸시를 따로 둔 것은 의도입니다. `git push`는 태그를 함께 가져가지 않습니다.

## 충돌

**충돌 해결…**은 커서 아래 파일의 충돌 구역을 나열하고 각 구역마다 *우리 것*, *그들 것*, *양쪽*, 또는 열어 둠
가운데 하나를 고르게 합니다. 그다음 **파일 쓰기** 또는 **쓰고 스테이징**입니다. 한 구역이라도 열려 있으면
스테이징을 거절하며(Git은 `<<<<<<<` 표시도 군말 없이 커밋합니다), 표시를 읽을 수 없는 파일은 짐작하는 대신
건드리지 않습니다. 양쪽을 손으로 엮어야 하는 구역이라면 **편집기에서 열기**가 버튼 하나 거리에 있습니다.

## 리베이스

**리베이스…**는 업스트림보다 앞선 커밋 — 아직 아무도 가지지 않은 커밋 — 을 나열하고, 브랜치를 다시 쓰기 전에
스쿼시하거나 픽스업으로 붙이거나 버리거나 순서를 바꾸거나 메시지를 고치게 해 줍니다. 리베이스가 충돌에서 멈추면
같은 창이 **계속** / **커밋 건너뛰기** / **리베이스 중단**으로 바뀌므로, 절반쯤 끝난 리베이스를 터미널에서
마무리할 필요가 없습니다.

## 파일 무시와 자격 증명

- **이 파일 무시…**, **이 파일 유형 무시…**, **이 폴더 무시…**는 알맞은 패턴을 `.gitignore`에 적습니다. 있어야
  할 자리에 고정되므로 *이* `build` 폴더를 무시한다고 해서 `build`라는 이름의 모든 폴더가 무시되지는
  않습니다.
- **자격 증명…**은 이 저장소가 어떻게 인증하는지 알려 줍니다. SSH인지 HTTPS인지, 자격 증명 도우미가 설정되어
  있는지, SSH 에이전트가 실행 중이며 키를 쥐고 있는지. 도움이 되는 경우 동작 하나만 제안합니다. Git이 자격
  증명을 macOS 키체인에 두게 하는 것입니다. 플러그인은 암호문을 묻지도, 보여 주지도, 저장하지도 않습니다.

## 참고

- 플러그인은 `/usr/bin/git`의 시스템 Git 또는 **설정 ▸ Git**에서 선택한 프로그램을 사용합니다. Git이 없으면 명령은 Git을 쓸 수 없다고 알립니다. (Xcode Command Line Tools를 설치하면 함께 들어옵니다.)
- 저장소 상태는 폴더마다 한 번 읽어 캐시하므로 큰 저장소를 넘겨 보아도 빠릅니다. 캐시는 트리를 바꾸는 명령
  뒤에 새로 고쳐지며, 앱 바깥에서 이루어진 커밋도 따라갑니다.
- 연결된 워크트리와 서브모듈을 지원합니다. 서브모듈 안의 파일은 상위 저장소가 아니라 *서브모듈의* 상태와
  브랜치를 보여 줍니다.
- 모든 목록에는 컨텍스트 메뉴가 있고, **Return**은 주 동작을 실행하며 **Cmd+R**은 창을 다시 불러옵니다.
- Git LFS, 서명된 커밋용 `gpg`, 자격 증명 도우미는 앱을 Finder에서 열었더라도 Homebrew와 MacPorts 폴더에서 찾습니다.
