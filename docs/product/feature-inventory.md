# Feature Inventory — Total Commander Parity Catalog

Master checklist for feature parity. **Grep by ID (F-xxx), do not load the whole file.**

- **Prio:** P1 = core parity (must), P2 = full parity (should), P3 = optional/macOS extra.
- **Status:** `todo` | `in-progress` | `done` | `n/a-macos` (with rationale) | `post-1.0`.
- Update the Status column the moment a feature is implemented AND tested.
- Source references: TC feature list (ghisler.com/featurel.htm), TC 11 help, plugin
  SDKs (ghisler.github.io).

A third fix was needed before any of it is usable by something that reads the keyboard: `performKeyEquivalent` is broadcast to every view in the window — which is how F5 copies wherever the cursor is — and the panel stood aside only when `firstResponder is NSText`. That repaired the command line and nothing else, so anything focusable that is not an NSText took the defect back: measured, `Ctrl+B` aimed at a non-NSText responder was claimed by the panel and opened a directory branch. The rule now asks the focused view, resolving up the hierarchy, and plugin views declare `rawKeyboard` in their manifest because an `NSView*` arriving across a C ABI cannot adopt a Swift protocol.
